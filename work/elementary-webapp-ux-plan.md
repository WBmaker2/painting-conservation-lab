# 중·고등학생 UX 개선 계획

작성일: 2026-09-23
대상: 중학생·고등학생, 교사 진행 및 자기 주도 사용
모드: full. 기준선 감사 완료 후 사용자 요청에 따라 우선순위 순서로 개선을 구현하고 같은 시나리오를 다시 점검합니다. 배포·커밋·푸시·HVC 등록은 범위에 없습니다.

## 승인된 구현 범위와 순서 (2026-09-23)

1. **EDU-UX-001 (P1, 먼저)** — 예측은 미선택으로 시작하고 서로 다른 가설 2개를 고르기 전 조사로 넘어갈 수 없게 합니다. 증거 관계는 학생이 조사 결과마다 직접 선택합니다. 선택 후 가상 모형의 비교 근거를 보여 주고 수정할 수 있게 합니다. 보존 행동을 먼저 고르고 기대 효과·불확실성·되돌림 생각을 학생이 적기 전에는 보고서를 만들지 않습니다. 자동 기본 결정이나 입력 안내문 저장은 제거합니다.
2. **EDU-UX-008 (P1, 회귀 중 추가 발견)** — 증거 화면에서 층 정보 표는 `layerDiagram` 조사를 완료한 뒤에만 공개합니다. 그 전에는 아직 층 정보를 확인하지 않았다는 안내와 조사 단계로 돌아가는 버튼을 보여 줍니다.
3. **EDU-UX-002 (P2)** — 시작 화면은 선택한 작품 한 점과 조건을 먼저 보여 주고 나머지 작품은 접힌 선택 목록으로 엽니다. 모바일에서 단계 수와 현재 위치가 보이게 하고 상단 바가 어색하게 줄바꿈되지 않게 합니다.
4. **EDU-UX-003 (P2)** — 학생 화면의 내부 ID·enum·규칙 키·P1 로드맵 표기를 한국어 조사명과 학습 설명으로 바꿉니다. 현재 코드에 있는 적외선·자외선 조사도 가상 결과임을 밝히고, PRODUCT/SURFACE 문서를 현행 12개 작품·5개 가상 조사 범위에 맞춥니다. 기존 기능·기록 형식은 보존합니다.
5. **EDU-UX-004 (P2)** — 지지체·바탕층·안료·바니시·호환 등 첫 등장 용어에 한 줄 풀이와 짧은 문장 시작틀을 제공합니다. 보존 용어의 기초 풀이는 Canadian Conservation Institute의 회화 구조 자료에 맞추고, 실제 처리를 권하는 문장은 추가하지 않습니다.
6. **EDU-UX-005 (P2)** — 보고서에서 학생의 판단·근거·불확실성을 다시 읽을 수 있게 하고, 개발용 자가점검 문구를 제거합니다. 한 번의 분명한 다음 행동으로 다른 가상 작품에 기준을 적용하게 합니다.
7. **EDU-UX-006 (P2)** — ‘처음부터 다시’ 후 초점을 시작 버튼으로 보내고, 포커스 표시와 시각 순서를 맞춥니다.
8. **EDU-UX-007 (P3)** — 예산을 실제 돈이 아닌 조사 점수로 처음부터 표시합니다.

### 구현·검토 경계

- 이번 날짜의 변경 내역을 앱 내 ‘업데이트 내역’과 `docs/CHANGELOG.md`에 기록합니다.
- 코드 파일은 500줄 미만으로 유지합니다. 필요하면 UI 조각·학생용 라벨을 별도 파일로 분리합니다.
- 회귀 점검은 같은 시나리오를 320·375·1280px에서 직접 따라가며 수행합니다. 예측 2개 선택, 조사, 증거 입력과 재시도, 결정·보고서 필수 입력, 저장·전이, 모바일 넘침, 키보드 초점, reduced-motion, 한국어 화면을 확인합니다.
- UX 구현·수용 단계에서는 자동화 테스트·빌드·배포를 실행하지 않았습니다. 이후 별도로 승인된 릴리스 단계에서는 검증과 배포를 진행하며, 결과는 문서 하단에 구분해 기록합니다. 실제 중·고등학생 사용자 연구·교사 승인이 아니며 VoiceOver는 구현·검증하지 않습니다.
- 보존 용어 한 줄 풀이 출처: Canadian Conservation Institute, “Know Your Paintings – Structure, Materials and Aspects of Deterioration” (support, ground, paint layers, varnish).

## 우선순위

### EDU-UX-001 · P1 — 핵심 판단 없이 보고서까지 완료할 수 있음

- 학습자 영향: 예측·증거 연결·보존 결정을 학생이 직접 하지 않아도 시스템 기본값으로 핵심 여정을 통과할 수 있습니다. 제품 목표인 근거 기반 판단과 보고서 작성이 연습되지 않은 채 완료로 보입니다.
- 브라우저 근거:
  - 첫 화면에서 표면 오염·후대 덧칠이 이미 선택 상태였습니다. 두 버튼을 누르지 않고 시작해도 조사 화면으로 이동했습니다.
  - 증거 단계는 ‘관찰을 가설과 연결하세요’라고 안내하지만, 관찰 3개와 가설 3개의 판정 9개를 모두 미리 채워 보여 줍니다. 학습자가 연결을 입력하는 조작은 없습니다.
  - 보존 결정 화면의 선택과 세 텍스트 칸을 모두 비운 채 ‘보고서 만들기’를 눌렀더니 유지 결정과 기본 문장이 들어간 보고서가 생성됐습니다. 불확실성 칸에는 입력 안내 문장 자체가 보고서 내용으로 들어갔습니다.
- 원인 가설: 시작 상태에서 두 가설을 기본 선택하고, 증거 연결을 자동 생성하며, 빈 결정 내용을 collectDecision에서 자동 문장으로 보완합니다.
- 제안:
  1. 예측 선택을 빈 상태로 시작하고 서로 다른 두 가설을 직접 고르기 전에는 시작을 막습니다. 메모는 선택 사항으로 둡니다.
  2. 증거표에서 한 관찰과 가설의 관계를 학생이 선택하게 하고, 선택 뒤 근거를 보여 줍니다. 세 번째 가설은 예측하지 않은 가설 비교로 분리할 수 있습니다.
  3. 보존 결정은 학생이 명시적으로 고르게 합니다. 빈 텍스트를 안내 문장으로 바꾸어 저장하지 말고, 짧은 문장 시작틀이나 근거 선택을 제공해 장문 작성 부담을 낮춥니다.
- 근거 코드: src/main.ts 29–38, 217–221, 239–249, 424–442.
- 같은 시나리오 재검증: 새로고침 후 320·375·1280px에서 시작 버튼이 가설 선택 전에 진행되지 않는지 확인합니다. 증거 연결에 실제 입력이 있는지, 잘못 고른 뒤 근거와 재시도가 보이는지 확인합니다. 결정·근거가 비어 있으면 보고서 생성이 막히고 포커스된 안내가 보이는지 확인합니다. 완성 보고서에는 학생이 고른 판단과 입력만 들어가야 합니다.

### EDU-UX-008 · P1 — 층 정보 조사 전에 가상 모형의 숨은 상태가 공개됨

- 학습자 영향: `visibleZoom`만 사용하고 층 정보를 확인하지 않았는데도 증거 화면의 층 표에서 가상 사건의 상태값을 볼 수 있었습니다. 학생이 조사 선택과 관찰을 통해 근거를 모으기 전에 설명 대상의 정답 상태를 알게 됩니다.
- 브라우저 근거: 구현 후 같은 시나리오를 점검하던 중, 층 정보 조사를 하지 않은 증거 화면에도 층 상태 표가 표시되는 것을 확인했습니다.
- 원인: 증거 화면이 `layerTable(currentRegion())`을 층 정보 조사 여부와 무관하게 렌더링했습니다.
- 수정: `src/main.ts`에서 관찰 목록에 `layerDiagram`이 있을 때만 표를 렌더링합니다. 없으면 아직 확인하지 않았다는 안내와 조사 단계로 돌아가는 버튼을 표시합니다.
- 같은 시나리오 재검증: `layerDiagram` 없이 증거 화면에 왔을 때 표와 상태값이 숨겨지는지, 안내와 돌아가기 버튼이 보이는지 확인합니다. 층 정보 확인을 실행한 다음에는 가상 모형이라는 한계 안내와 표가 표시되는지 320·375·1280px에서 확인합니다.
- 상태: 코드 수정과 paired 회귀 테스트를 완료했습니다. 로컬 브라우저 회귀 기록은 위에 있습니다. 최종 릴리스 단계의 검사·배포 판정은 문서 하단 기록을 따릅니다.

### EDU-UX-002 · P2 — 모바일에서 가설 입력이 작품 목록 뒤에 묻힘

- 학습자 영향: 320px에서 작품 12개가 한 열로 이어집니다. 첫 영역 선택 입력은 문서 기준 약 4,022px 지점, 작품 목록 끝은 약 3,869px 지점이었습니다. 800px 화면 높이에서 여러 화면을 내려가야 조작 패널에 도달합니다. 위쪽의 강한 시작 버튼은 그보다 먼저 보여 입력을 건너뛰게 할 수 있습니다.
- 근거: 320×800에서 페이지 높이 4,908px, 작품 카드 12개, 영역 입력 시작 4,022px. 문서 가로 넘침은 없지만 진행 단계 레일도 내부 가로 스크롤로 일부만 보입니다.
- 원인 가설: 모바일에서 시각 자료 전체 목록을 조건·실행 패널 앞에 쌓습니다.
- 제안: 현재 작품 한 점과 관심 영역·가설 입력을 우선 보여 주고, 나머지 작품은 ‘다른 작품 고르기’ 접기/선택 화면으로 엽니다. 다섯 단계를 항상 보이게 하거나 현재 단계와 전체 단계를 함께 표시합니다. 좁은 상단 바에서는 업데이트 내역과 브랜드가 여러 줄로 쪼개지지 않게 조정합니다.
- 근거 코드: src/main.ts 168–176, src/style.css 26–46, 67–80.
- 같은 시나리오 재검증: 320×800과 375×812에서 작품·영역·가설 선택의 첫 행동이 분명하고, 전체 가로 넘침이 없으며, 단계 4·5도 있다는 사실과 이동 방법이 보이는지 확인합니다.

### EDU-UX-003 · P2 — 내부 식별자와 개발 단계명이 학생 화면에 노출됨

- 학습자 영향: 조사 카드에 grime-thin::visibleZoom 및 still-night-apple/apple-shadow/visibleZoom이 보이고, 증거표에 visibleZoom·rakingLight·layerDiagram·thin-dust·even이 표시됩니다. 적외선·자외선 카드의 P1은 개발 로드맵 용어로 보입니다. 중학생에게는 의미를 설명하지 않고, 고등학생에게도 학습 내용보다 구현 정보를 노출해 신뢰를 낮출 수 있습니다.
- 근거: work/elementary-webapp-ux-evidence/investigation-results.png, evidence-320.png; src/main.ts 184–187, 239–252, 269–275; engine/observationRules.ts 27–38.
- 원인 가설: 관찰 카드에서 ruleId와 observationKey를 직접 출력하고, 모델 enum을 층 표에 그대로 씁니다.
- 제안: 학생 화면에서는 한국어 조사명과 설명만 표시하고 내부 키는 개발자 로그·내보내기 데이터에만 둡니다. P1 표시는 제거하거나 학생이 이해할 수 있는 조사 분류로 바꿉니다. PRODUCT.md는 적외선·자외선을 P1 범위 밖으로 적었지만 실행 앱과 변경 이력에는 표시되어 있어, 교육 담당자가 기능 범위도 함께 확정해야 합니다.
- 같은 시나리오 재검증: 조사·증거·보고 화면에서 영문 enum, 경로 키, 개발 우선순위 문자열이 보이지 않는지 확인합니다.

### EDU-UX-004 · P2 — 핵심 미술 보존 용어의 첫 풀이와 행동 안내가 부족함

- 학습자 영향: 지지체, 표면침적층, 바니시, 안료, 호환표 등은 중학생에게 낯설 수 있고 고등학생도 미술·화학 배경에 따라 이해가 다릅니다. ‘예측으로 기록’은 버튼 선택이 실제 기록과 어떻게 연결되는지 모호합니다. ‘층 구조 표 (대체 수단)’은 학생에게 개발 설명처럼 보입니다.
- 근거: 초기 안내와 예측 UI, 증거 단계의 호환표·층 구조 표 문구. 실제 화면 텍스트는 language-audit 기록 참고.
- 제안: 핵심 용어를 유지하고 첫 등장에 한 줄 풀이를 붙입니다. 보존·재료 관련 정의와 적외선·자외선 설명은 전문가 검토를 거칩니다. 지시는 실제 조작과 일치하도록 동사를 고칩니다. 대체 표는 언제 쓰는지 학생 관점으로 설명합니다.
- 같은 시나리오 재검증: 중학생·고등학생 모의 패널이 지시를 자기 말로 바꾸고, 각 용어를 예시와 함께 설명하며, 버튼 결과를 예측하는지 확인합니다.

### EDU-UX-005 · P2 — 완료 화면에 개발 검증 문구가 있고 다음 학습 행동이 없음

- 학습자 영향: 완료 보고서 아래에 ‘완료 판정 자가점검’, ‘통과’, ‘1+2+3=6 허용’이 표시됩니다. 학습자가 다음에 할 수 있는 일은 저장·JSON 내보내기·인쇄·처음부터 다시에 머뭅니다.
- 근거: src/main.ts 269–275, 320–327; 브라우저 완료 화면 스냅샷.
- 제안: 자가점검은 학생 화면에서 빼거나 교사용 상세 영역으로 이동합니다. 보고서에 이번 판단의 핵심 근거와 남은 불확실성을 짧게 요약하고, 다른 가상 사례에 같은 기준을 적용하는 다음 행동을 제공합니다.
- 같은 시나리오 재검증: 보고서에서 자기 판단의 근거와 불확실성을 다시 확인할 수 있고, 전이 과제를 한 번의 분명한 행동으로 시작할 수 있는지 확인합니다.

### EDU-UX-006 · P2 — ‘처음부터 다시’ 뒤 키보드 초점이 시작 버튼을 건너뜀

- 학습자 영향: 보고 화면에서 처음부터 다시를 누르면 초점이 ‘작품과 관심 영역’ 제목으로 이동합니다. 그 제목에서 Tab을 누르면 작품 카드로 이동해, 제목보다 앞에 있는 ‘연구 시작하기’ 버튼을 순방향 키보드 이동에서 건너뜁니다. 프로그램 초점의 표시도 보이지 않았습니다.
- 근거: 320px 화면에서 reset 후 activeElement가 h2, 다음 Tab 두 번이 작품 카드 A·B로 이동. src/main.ts의 setPhase 자동 초점과 heroView 순서.
- 제안: 초기화 후 시작 버튼이나 시작 제목 앞의 명확한 위치로 초점을 이동하고, Tab 순서와 포커스 표시가 실제 시각 순서와 맞는지 확인합니다.
- 같은 시나리오 재검증: 보고 화면에서 키보드로 재시작한 뒤 Tab·Shift+Tab만으로 시작 버튼과 핵심 조작을 순서대로 실행합니다.

### EDU-UX-007 · P3 — 예산 점수가 실제 비용처럼 들릴 수 있음

- 학습자 영향: 첫 화면은 ‘예산 6점’이라고만 해 게임 규칙과 실제 비용의 구분이 이후 화면보다 약합니다.
- 근거: 첫 화면 설명과 이후 ‘남은 예산 (게임 단위)’ 문구. PRODUCT.md는 예산이 실제 비용이 아니라고 정함.
- 제안: 첫 등장에 ‘조사 점수 6점(실제 비용 아님)’처럼 명확히 알립니다.
- 같은 시나리오 재검증: 중·고등학생 모의 패널이 점수가 실제 돈이나 처리 비용이 아님을 설명하는지 확인합니다.

## 구현 후 수용 기준

- EDU-UX-001과 EDU-UX-008은 수정 후 동일 학습 경로의 브라우저 회귀를 통과했습니다. 따라서 P1 UX 게이트는 통과했습니다. 실제 학생 평가·전문가 검토는 이 수용 판정에 포함되지 않습니다. 별도 승인된 릴리스 검증과 배포 증거는 아래 기록을 참조합니다.
- 320·375·1280px에서 같은 학습 경로를 확인합니다.
- 중학생·고등학생 모의 패널에서 예측·증거·결정 입력이 학생 행동으로 남는지 확인합니다.
- 키보드 경로, reduced-motion, 실제 화면의 한국어 문구, 보고서 전이 행동을 확인합니다.
- 가상 조사 결과와 실제 측정·처리의 경계가 모든 관련 단계에서 보입니다.

## 2026-09-23 구현 후 수동 회귀 기록

- ego-browser의 로컬 Vite 앱에서 320×800, 375×812, 1280×900으로 같은 가상 작품·확대 조사 경로를 완료했습니다. 각 단계의 `documentElement.scrollWidth - clientWidth`는 0px이었습니다.
- 가설 미선택 시작과 증거 판단 미완료가 차단됐고, alert가 안내를 전달했습니다. 판단을 고른 뒤에만 모형 결과·이유가 공개됐고, 학생 판단을 바꾸는 재시도도 확인했습니다.
- 결정 미선택·기대 효과 누락이 각각 차단됐습니다. 결정 행동과 세 설명을 입력한 뒤 보고서에 동일 문구와 학생/모형 판단이 구분되어 나타났습니다.
- 내부 ID·관찰 키·P1·`undetermined`가 학습자 조사·증거·보고 화면에 나타나지 않았습니다. 층 구조 용어 풀이와 실제 측정이 아니라는 안내가 보였습니다.
- **추가 P1, EDU-UX-008 재검증 통과:** ego-browser에서 320×800·375×812·1280×900으로 같은 경로를 다시 완료했습니다. `visibleZoom`만 마친 증거 화면에는 층 표가 없고, 미확인 안내와 조사 단계로 돌아가는 버튼이 보였습니다. `layerDiagram` 조사 후에는 층 표와 ‘실제 두께나 재료를 측정한 결과가 아닙니다’ 안내가 나타났습니다. 각 화면에서 `scrollWidth - clientWidth`는 0px이었습니다. 앱 상태를 통해 확인한 수치: 320px은 305/305, 375px은 360/360, 1280px은 1265/1265(`clientWidth/scrollWidth`).
- 완료 후 다른 가상 작품으로 전이하면 작품·조사 점수·가설·관찰이 새 상태로 시작하고, 시작 CTA에 보이는 3px 포커스 링이 생겼습니다. Tab·Shift+Tab 경로와 reduced-motion 정적 테두리를 확인했습니다. 전이 CTA에는 한 개의 gi-pulse가 보였습니다.
- 스크린샷: `work/elementary-webapp-ux-evidence/post-implementation-320-reset-focus.png`.
- UX 점검 단계에는 실제 청소년 이해도 조사·전문가 검토·VoiceOver·콘솔/네트워크 전체 점검·릴리스 빌드·배포를 포함하지 않았습니다. 이후 승인된 릴리스 단계의 자동 검사·빌드·배포 상태는 하단 별도 기록에 구분합니다.
